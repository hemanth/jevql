The Semantic Void in Traditional SQL

Relational databases excel at exact equality, numbers, and dates. But modern data is semi-structured: support tickets, product reviews, emails, and error logs.

Keyword matching and regex fail on nuance and sarcasm. Vector search finds similar embeddings but cannot do calibrated conditional logic, multi-label classifications, or relational aggregations.

The JevQL Optimization Engine

Calling LLMs row-by-row in userland is slow, uncalibrated, and expensive. JevQL introduces Relational Pushdown: deterministic filters prune rows before AI execution ($0 cost).

Surviving rows undergo Speculative Fan-out: all NOUL, CHOICE, and SCORE questions for a row are bundled into a single System One forward pass with SHA-256 caching.

Architecture Blueprint

Monochrome execution topology: In-tree pushdown filtering, single-pass batching, and TypeSafe System One.

3-Line Quick Start (Node.js)

Query any array of JavaScript objects or local JSON/CSV files with zero ceremony:

import jevql from 'jevql';

const rows = await jevql(`
  SELECT id,
    CHOICE(body, 'Team', ['billing', 'security', 'tech']) AS dept
  FROM data
  WHERE NOUL(body, 'Urgent escalation?') > 0.8
`, tickets);

Postgres Pushdown & REPL

Execute relational pushdown directly against PostgreSQL tables and inspect in terminal:

# Launch interactive CLI REPL
$ npx jevql -f tickets.json

# Or query a live Postgres database
SELECT customer,
       SCORE(feedback, 'Frustration', ['calm', 'angry']) AS fr
FROM postgres('postgres://...').tickets
WHERE status = 'open'
ORDER BY fr DESC;
